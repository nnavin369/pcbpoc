📌 Overview

This framework is built using Behavior Driven Development (BDD) principles with Playwright for browser automation and Cucumber.js for Gherkin-based test execution. It is designed to be scalable, maintainable, and easy to extend for any new QA engineer joining the team.

🎯 Key Goals

  • Tests written in plain English (Gherkin)
  • Login once — reuse session across tests
  • Auto screenshot on every failure
  • Structured logging on every step
  • Rich Allure HTML reports

⚙️ Setup & Installation

1

Clone the repository and install dependencies

git clone <repository-url>
cd newrez-bdd-playwright
npm install
2

Install Chromium browser

npx playwright install chromium
3

Verify setup with a dry run

npx cucumber-js --dry-run --publish-quiet

You should see all scenarios listed with skipped status — no errors.

🏗️ Framework Design Principles

🔐 Smart Session Management

@login scenarios get a fresh isolated browser per scenario. @dashboard scenarios share a single logged-in session — login happens once in BeforeAll.

📋 Single Source of Truth

All config (URL, credentials, timeouts, browser settings) lives in config/env.js. Change one file to update the entire framework.

🧩 Page Object Model

Every page has its own class extending BasePage. Selectors and actions are fully encapsulated — steps never contain selectors.

📸 Auto Screenshot on Failure

AfterStep hook automatically captures a full-page screenshot on any failure and attaches it to the Allure report.

📝 Structured Logging

Every action is logged with timestamp, level (INFO / STEP / ERROR), and message — making debugging effortless.

[2026-08-07 18:25:51] ✅ INFO  | Login successful
[2026-08-07 18:25:52] 🔷 STEP  | Clicking: #login-disable
[2026-08-07 18:25:53] ❌ ERROR | Step failed — screenshot captured

🔌 Zero Core Changes

Adding a new feature never requires changes to BasePage, hooks, sessionManager, logger, or env. Only world.js and cucumber.js need 1 line each.

➕ How to Add a New Feature

Follow these 5 steps every time you add a new feature. Example: adding a Loan Details feature.

1

Create features/loanDetails.feature

Write Gherkin scenarios using a new tag @loanDetails

@loanDetails
Feature: Loan Details
  As a logged-in user
  I want to view loan details
  So that I can verify loan information

  @smoke
  Scenario: View loan details page
    Given I am on the dashboard
    When I navigate to loan details for "1234567"
    Then I should see the loan details page
2

Create pages/LoanDetailsPage.js

Define selectors and page actions — always extend BasePage

'use strict';

const BasePage = require('./BasePage');

const SELECTORS = {
  loanNumber: '.loan-number',
  loanStatus: '.loan-status'
};

class LoanDetailsPage extends BasePage {
  async getLoanNumber() {
    return this.getText(SELECTORS.loanNumber);
  }
}

module.exports = LoanDetailsPage;
3

Create steps/loanDetailsSteps.js

Map each Gherkin step to a page action

'use strict';

const { When, Then } = require('@cucumber/cucumber');
const { expect } = require('@playwright/test');

When('I navigate to loan details for {string}', async function (loanId) {
  await this.loanDetailsPage.navigate(`/Loan/Details/${loanId}`);
});

Then('I should see the loan details page', async function () {
  const num = await this.loanDetailsPage.getLoanNumber();
  expect(num).toBeTruthy();
});
4

Register in support/world.js — 2 lines only

// 1. Add import at the top
const LoanDetailsPage = require('../pages/LoanDetailsPage');

// 2. Add inside init() method
this.loanDetailsPage = new LoanDetailsPage(this.page);
5

Register in cucumber.js — 1 line only

'--require steps/loanDetailsSteps.js',  // ← ADD THIS
✅ That's it! Run npm test — your new feature is live. Zero changes to core framework files.

📏 Golden Rules for QA Engineers

🚫 Never put selectors in step definitions. All selectors belong in Page Objects only.
🚫 Never hardcode credentials in steps or features. Always use config/env.js.
🚫 Never modify BasePage, hooks, sessionManager, logger, or env when adding a new feature.
✅ Always extend BasePage for every new page object.
✅ Always add a feature-level tag (e.g. @loanDetails) to every new feature file.
✅ Use @dashboard tag for any feature that needs a logged-in session to avoid repeated logins.
