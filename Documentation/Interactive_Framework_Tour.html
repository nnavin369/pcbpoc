🚀 Shellpoint Insight Automation Framework Tour

Comprehensive Visual Guide to Playwright + Cucumber BDD + Page Object Model + Allure Reporting

1. BDD Layer

📝 Feature Files

Plain-English test scenarios written using Gherkin syntax (Given, When, Then) for maximum business clarity.

Scenario: Verify Loan ID Search
  Given I am on the dashboard
  When I search for Loan ID "555835905"
  Then the API response status code should be 200
2. Step Layer

⚙️ Step Definitions

Connects Gherkin sentences to JavaScript actions and calls methods on our Page Objects.

When('I search for Loan ID {string}', async function(id) {
  await this.dashboardPage.fillSearch('loanid', id);
  await this.dashboardPage.submitSearch();
});
3. POM Layer

🏢 Page Object Model

Encapsulates locators, clicks, waits, and security masking inside reusable page classes.

class BasePage {
  async fill(selector, value) {
    const isSensitive = /pass|pwd/i.test(selector);
    logger.step(`Filling ${selector} with ${isSensitive ? '********' : value}`);
    await this.page.locator(selector).fill(value);
  }
}
4. API Interceptor

📡 Network Interceptor

Listens to background XHR/Fetch API responses in real time, capturing HTTP status codes and JSON payloads.

const interceptor = new ApiInterceptor(this.page);
interceptor.startCapture();
// ... actions ...
const json = interceptor.getResponseJson('/DataApi/Info/');
5. Session & Video

🎬 Session & Video Handling

Reuses authenticated session across workers and attaches HD videos exclusively for failed scenarios.

// In support/hooks.js:
if (isFailed) {
  await this.attach(videoBuffer, 'video/webm');
} else {
  fs.unlinkSync(videoPath); // Clean up passing videos
}
6. Allure Reporting

📊 Rich HTML Reports

Generates interactive summary tables with green/red badges, attached JSON logs, and failure screenshots.

npm run report:generate
npm run report:open

📋 Execution Flow & Business Phases

  1. Phase 1: User Authentication (features/login.feature) — Validates valid login, invalid credentials, and required field validation.
  2. Phase 2: Loan Search on Dashboard (features/loanSearch.feature) — Tests search by Loan ID, Borrower Name, Street, City, State, and Zipcode.
  3. Phase 3: Loan Details Multi-Tab Verification (features/loanDetailsTabs.feature) — Sequentially navigates all 14 tabs with UI keywords and API status checks.
  4. Phase 4: Loan Search API Validation (features/loanSearchApiValidation.feature) — Validates status 200, Address, InvestorId, Borrower 1 & 2 values, and pretty-prints JSON.

💻 Quick Command Cheatsheet

Command Description Profile / Scope
npm test Runs all 4 phases in sequential order Sequential (Default)
npm run test:api Runs API response & payload verification API Suite
npm run test:loantabs Runs 14-tab multi-tab verification suite Multi-Tab Suite
npm run test:parallel Runs test suite in parallel across 3 workers Parallel (3 Workers)
npm run report:open Opens live Allure HTML test execution report Reporting Server
